02 — Bilan

Le pour et le contre

Avantages

  • Gratuit, sans limite de durée.
  • Pas de serveur, rien à maintenir.
  • Chaque modif des données est gardée dans git.

Défauts

  • Le site est forcément public, même en payant.
  • Le code se vérifie dans ton navigateur, pas sur un serveur.
  • Lecture seule : on édite les données à la main.

04 — Sous le capot

Ce code protège-t-il ? Spoiler : non.

  1. Code en clair dans le HTML. Clic droit, « Inspecter », et on le lit. Zéro protection.

  2. Code haché (ce qu'on fait ici). La page ne contient que l'empreinte SHA-256 du code :

    f6563999cf206aa7c0113c3378785452f0950c37bf22742c5b8cf79ac3d2e2fb

    Un hash ne s'inverse pas. Mais 4 chiffres, c'est 10 000 essais, faits en une fraction de seconde.

    0000

  3. Et de toute façon… Le hash protège la porte, pas le contenu. Les données sont dans data.json, lisible par tous, comme tout le repo.

Sur GitHub Pages, tout est public. Parfait pour une vitrine, jamais pour du confidentiel. Une vraie connexion demande un serveur : voir Vercel et Raspberry.
